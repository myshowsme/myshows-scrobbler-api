Go by the HTTP status of the response:

| Code | Meaning |
|---|---|
| `401` | The token is invalid or revoked. Ask the user to update it |
| `4xx` | The request is wrong, retrying is pointless |
| `5xx` | Server error, retrying is fine |

Don't depend on the structure of the error body: decide whether to retry based on the
status, and show the body to the user as is.

## Retries

On network errors and `5xx`, make up to three attempts with exponential backoff (1 s, 2 s).
The request timeout is 5 seconds. Don't retry on `4xx`.

::note{to="/en/scrobbling/lifecycle"}
A separate note on `/stop`: if it failed because of the network, don't treat the session
as closed. Keep sending `/pause` and retry `/stop` on the next tick.
::
