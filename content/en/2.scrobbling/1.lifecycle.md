Three endpoints describe the lifecycle of a single view.

| Event on your side | Endpoint | What MyShows does |
|---|---|---|
| The user starts watching | `POST /start` | opens a viewing session |
| The user keeps watching / pauses | `POST /pause` | updates the position |
| The user finishes watching | `POST /stop` | closes the session and **marks the view** |

The key point: a view is counted on `/stop`, and only if `progress` is high enough.

## Watched threshold

Treat a view as complete from **80%** onwards. This is the default in the reference
client, and it matches the Trakt and Simkl threshold. A reasonable range for a user
setting is 50–95%. If the user stops watching before the threshold, don't send `/stop`
at all: the session closes on its own.

## Recommended loop

::steps{level="3"}

### Playback starts

`POST /start` with the current `progress`.

### Then every 10–30 seconds

`POST /pause` with the updated `progress`. Don't send a request if progress hasn't moved
since last time. The reference client skips such ticks. On seek and pause, send `/pause`
right away, outside the schedule.

### Progress passes the threshold

`POST /stop`. After that, send nothing more for this session.

### Playback stops before the threshold

Send nothing.

::

::warning
---
icon: i-lucide-wifi-off
---
**Network failure.** If `/stop` didn't go through, don't treat the session as closed.
Keep sending `/pause` and retry `/stop` on the next tick, so a dropped connection
doesn't eat the watched mark.
::
